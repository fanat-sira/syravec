# Original illustration sizes

SyraVec keeps two independent source libraries. `large` uses `Тестовое _ иллюстрации(2).zip`, supplied locally as `originals/assets.zip`; `small` uses `Тестовое _ иллюстрации(3).zip`, supplied as `originals/assets-small.zip`. Original filenames are also accepted. Neither archive belongs in Git or container images.

## Geometry contract

All objects use a common factor of **1 native source unit per logical canvas unit**. The source viewBox determines an object's dimensions. There is no per-layer scale in scene version 2, the editor controls, the API scene, or the model plan. Zoom and pan affect the view only.

| Format | Large | Small |
| --- | --- | --- |
| Square | 1000 × 1000 | 500 × 500 |
| Landscape | 1000 × 633 | 500 × 317 |
| Portrait | 750 × 1000 | 375 × 500 |

Switching illustration size replaces the source SVG for every built-in layer and changes the canvas dimensions. Logical IDs, normalized centers, rotations, order, palette, opacity, visibility, and lock flags are retained. Small vectors have their own paths and can differ slightly in proportions or detail. They are not generated by transforming large vectors.

Objects may extend beyond the canvas. Format changes and the layout optimizer do not shrink objects. Native SVG backgrounds use their own viewBox with `xMidYMid slice`; square uses the square source, landscape and portrait allow proportional cropping. Palette sample tables are not backgrounds. Backgrounds have no editable layer transform.

Custom SVGs retain their original dimensions. An uploaded asset records the composition size at upload; it can be used in that size only. When a custom vector is present, the composition size control explains why switching is unavailable. No alternate custom source is manufactured. Custom vectors remain supported by selection rearrangement.

## Preparation and correspondence

[`prepare-assets.mjs`](../scripts/prepare-assets.mjs) handles both sets in one preparation run. The stable logical IDs are:

| Object | Main | Background variant |
| --- | --- | --- |
| Puzzle | `puzzle-main` | `puzzle-background` |
| Book | `book-main` | `book-background` |
| Phone | `phone-main` | `phone-background` |
| Headphones | `headphones-main` | `headphones-background` |
| Lamp | `lamp-main` | `lamp-background` |
| Wallet | `wallet-main` | `wallet-background` |
| Pen | `pen-main` | `pen-background` |
| Folder | `folder-main` | `folder-background` |
| Coin | `coin-main` | `coin-background` |
| Flowers | `flowers-main` | `flowers-background` |

Large sources use an explicit name mapping. Small sources use an explicit 20-entry correspondence verified against the supplied archives, including their unrelated `Group ...` filenames. Native dimensions are read independently; flowers and coin need not be exactly half-sized. Color roles are checked and missing or ambiguous sources stop preparation. The manifest records each exact source filename, SHA-256 hash, path count, and measured geometry separately under `sets.large` and `sets.small`. Actual backgrounds are selected by the explicit `Фон.svg`, `Фон-1.svg`, and `Фон-2.svg` names.

Original SVG bytes are copied unchanged. Both sets are measured with librsvg and staged before the versioned library directory and manifest are published. API and web use the same prepared manifest and sources. Missing either archive blocks fresh startup. Deployment checks for both archives before replacing running services.

## Older projects

Browser storage and project files migrate old scenes to version 2. Migration preserves layer IDs, normalized centers, rotations, palette, order, visibility, opacity, and lock state; saved generation snapshots are migrated too. Old individual scales are discarded. The editor shows a migration notice because native sizes cannot reproduce every old composition visually. Undo for newly completed actions continues to use whole-scene snapshots.

## Verification

Unit and browser checks cover independent source path data, native size ratios, all six canvas dimensions, removed resize controls, legacy migration, custom-SVG restrictions, Undo, and vector export. The source-preparation/container checks use two independent **synthetic** archives, with different geometry and the explicit small-source filename mapping. These fixtures do not substitute for validating the private originals.

After preparing and serving the real originals, run:

```bash
python3 scripts/check-svg-source-sets.py http://127.0.0.1:3000 \
  originals/assets.zip originals/assets-small.zip --originals
```

This compares every served object and background byte-for-byte with its archive entry and verifies hashes, path counts, distinct source URLs, and all 20 logical pairs. The real main phone must contain **155 paths in large and 96 in small**. Merely changing its viewBox cannot satisfy this check.
